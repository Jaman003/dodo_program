**وضعیت در ۱۲ نوامبر ۲۰۲۶:** بیلد **iOS 2.2.2 (113)** برای پردازش در App Store Connect بارگذاری شده است. هنوز به App Review ارسال نشده و عرضهٔ آن در App Store اعلام نشده است. پردازش، بررسی اپل و انتشار سه مرحلهٔ جدا هستند.

تغییرات زیر فقط مربوط به این بیلد iOS است. حداقل سیستم iOS 15 و هسته همچنان Xray 26.10.31 است. این تغییرات به معنای به‌روزرسانی Android APK 2.2.0 (2107)، macOS یا Windows نیست.

## JSON کامل: `env` و `version`

فیلدهای ریشهٔ `env` و `version` همراه پروفایل کامل حفظ می‌شوند. سندی که تنها `outbounds` و این فیلدها را دارد دیگر به چند لینک مستقل تبدیل نمی‌شود. مجموعهٔ عادی خروجی‌های مستقل، اگر نیاز به پروفایل کامل نداشته باشد، همچنان مجموعه باقی می‌ماند.

هستهٔ مشخص‌شده، `version.min` / `version.max` را پیش از اجرا بررسی می‌کند؛ شرط ناسازگار نادیده گرفته نمی‌شود. مقادیر پشتیبانی‌شدهٔ `env` برای اتصال یا نمونهٔ کمکی مربوط اعمال و پس از پایان تأییدشده بازیابی می‌شوند تا تنظیمات یک سرویس به نشست بعدی منتقل نشود. مسیر منابع، تنظیمات برنامه، Go/TUN، پراکسی و اعتماد TLS محافظت می‌شوند. نیاز فعالِ پشتیبانی‌نشده با خطای روشن رد می‌شود و مقدارهای ENV در متن خطا قرار نمی‌گیرند.

## HTTP GET / HEAD از مسیر پروفایل

اتصال و بررسی HTTP از آماده‌سازی مشترک استفاده می‌کنند: پراکسی یا متعادل‌کنندهٔ انتخاب‌شده، وابستگی خروجی‌ها، DNS، مسیریابی، تنظیمات انتقال و داده‌های جغرافیایی مربوط. آزمایش در یک نمونهٔ کمکی و ایزولهٔ Xray انجام می‌شود و VPN فعال را دوباره وصل نمی‌کند. شکست HTTP با موفقیت اتصال مستقیم یا بازبودن پورت TCP جایگزین نمی‌شود.

آماده‌سازی داده‌های جغرافیایی در بررسی HTTP پروفایل Hysteria2 اصلاح شده است. چون Hysteria2 بر UDP است، در حالت TCP همچنان بررسی HTTP به‌طور خودکار برای آن انتخاب می‌شود. TCP معمولی زمان خام را بدون تقسیم نشان می‌دهد؛ فقط DoDo Ping تخمینی، HTTP GET را بر ۳٫۳ تقسیم می‌کند. این بررسی آزمایش سرعت یا آزمون کامل تونل VPN فعال نیست.

## DNS، DoH تفکیک‌شده و FakeDNS محدود

هماهنگی DNS هسته با تونل سیستم، DoH تفکیک‌شده و نام‌های مستعار محلی DNS بهبود یافته است. طول زنجیرهٔ نام‌های مستعار محدود است و چرخه‌ها بررسی می‌شوند. تنظیمات مبهم تنها برای اجراشدن به‌زور بازنویسی نمی‌شوند.

پروفایل‌های سازگار FakeDNS با مجموعه‌آدرس‌های استاندارد که ارائه‌دهنده صریحاً تعیین کرده باشد پشتیبانی می‌شوند؛ این به معنای پشتیبانی عمومی از هر مجموعه‌آدرس، DNS ترکیبی یا Lua نیست. برای پروفایل FakeDNS بررسی جداگانهٔ HTTP موجود نیست؛ نمایش `N/A` در این بررسی به‌تنهایی خرابی VPN را ثابت نمی‌کند.

## FinalMask و پارامترهای قطعه‌بندی

URI سازگار می‌تواند `fm`، `fragment` و `fragmentPackets` / `fragmentLength` / `fragmentInterval` داشته باشد. از پاسخ واقعی و موفق HTTP، فیلدهای زیر پذیرفته می‌شوند:

</div>

```http
fragmentation-enable: true
fragmentation-type: xray
fragmentation-packets: tlshello
fragmentation-length: 50-100
fragmentation-delay: 10-20
fragmentation-maxsplit: 100-200
```

<div dir="rtl">

`fragmentation-interval` نام جایگزین هدر HTTP برای تأخیر است، نه فرمان تغییر نام فیلدهای JSON کامل. اعمال ماسک از هدر به `fragmentation-enable: true` و نوع `xray` نیاز دارد.

اولویت با **JSON کامل** است؛ پس از آن **ماسک صریح URI** و سپس **هدرهای پاسخ** قرار می‌گیرند. دو ماسک خودکار روی هم قرار نمی‌گیرند. JSON ارائه‌دهنده بی‌خبر اصلاح نمی‌شود و حالت فعالِ ناسازگار رد می‌شود. قطعه‌بندی خودکار TCP روی پروفایل UDP-only / Hysteria اعمال نمی‌شود. ویرایشگر جداگانه‌ای برای همهٔ پارامترهای ماسک در رابط وجود ندارد.

## موارد بدون تغییر

کلیدهای درست، ترتیب پروفایل‌ها و تنظیمات سرور صرفاً به دلیل به‌روزرسانی کلاینت نیاز به تغییر ندارند. بررسی گواهی TLS ضعیف نمی‌شود و SDK تازه‌ای اضافه نشده است. واردکردن موفق یا بررسی یک URL تضمین کارکرد همهٔ نودها و شبکه‌ها نیست؛ ارائه‌دهنده همچنان باید DNS، تگ‌ها و تنظیمات انتقال خود را بررسی کند.
