# مسیریابی، داده‌های جغرافیایی و تنظیمات شبکه

قواعد مسیریابی مشخص می‌کنند کدام مقصد مستقیم باز شود، از پروکسی عبور کند یا مسدود شود. قالب سادهٔ قواعد DoDo با پیکربندی کامل Xray تفاوت دارد. JSON کامل Xray را در فیلدهای این قالب قرار ندهید.

مبنای این صفحه نسخهٔ iOS 2.2.0 و Android APK 2.2.0 (2107) است. امکانات نسخه‌های دیگر باید جداگانه بررسی شوند.

**بیلد آماده‌شدهٔ iOS 2.2.2 (113)** هماهنگی DNS سازگار، split DoH و نام‌های مستعار محلی با محافظت در برابر چرخه را بهبود می‌دهد. پروفایل صریح و سازگار FakeDNS با مجموعه‌آدرس استاندارد پشتیبانی می‌شود، نه هر ساختار ترکیبی DNS یا Lua. این تغییر قالب کوچک `autorouting` را گسترش نمی‌دهد؛ محدودیت‌های DNS/FakeDNS آن در ادامه برقرارند. [محدودهٔ پشتیبانی و وضعیت پردازش در App Store Connect](ios-2.2.2.fa.md) را ببینید؛ بیلد هنوز به App Review ارسال نشده و عرضهٔ فروشگاهی اعلام نشده است.

## قواعد ثابت

```json
{
  "Name": "Demo rules",
  "GlobalProxy": true,
  "DomainStrategy": "IPIfNonMatch",
  "DirectSites": ["domain:example.invalid"],
  "DirectIp": [],
  "ProxySites": ["full:proxy.example.invalid"],
  "ProxyIp": [],
  "BlockSites": ["geosite:category-ads-all"],
  "BlockIp": []
}
```

| فیلد | کاربرد |
| --- | --- |
| `Name` | نام نمایشی پروفایل قواعد. |
| `GlobalProxy` | تنظیم پروکسی سراسری برای این پروفایل قواعد. |
| `DomainStrategy` | راهبرد تبدیل دامنه. قالب راه‌دور مقادیر `AsIs`، `IPIfNonMatch` و `IPOnDemand` را می‌پذیرد. |
| `DirectSites` / `DirectIp` | مقصدهای اتصال مستقیم. |
| `ProxySites` / `ProxyIp` | مقصدهایی که از پروکسی عبور می‌کنند. |
| `BlockSites` / `BlockIp` | مقصدهای مسدودشده. |

فهرست دامنه‌ها، نام دامنه و ورودی‌های پشتیبانی‌شدهٔ `domain:`، `full:`، عبارت بررسی‌شدهٔ `regexp:` و `geosite:` را می‌پذیرد. فهرست IP شامل آدرس IP، شبکهٔ CIDR و `geoip:` است. دسته‌های ارجاع‌شده باید در فایل‌های موجود وجود داشته باشند.

### افزودن پروفایل محلی

JSON را با UTF-8 و سپس Base64 یا Base64URL کدگذاری کنید. Base64URL بدون `=` پایانی برای لینک مناسب‌تر است؛ Base64 معمولی را می‌توان یک بار percent-encode کرد.

```text
dodo://routing/add/{BASE64_UTF8_JSON}
dodo://routing/onadd/{BASE64_UTF8_JSON}
dodo://routing/off
```

هر دو دستور `add` و `onadd` پروفایل را ذخیره و فعال می‌کنند. دستور `off` بدون حذف، آن را غیرفعال می‌کند. نام کاربری، رمز عبور، پورت، query یا fragment اضافه نکنید. قواعد در اتصال بعدی اعمال می‌شوند؛ VPN فعال خودکار قطع و وصل نمی‌شود.

برای باز کردن برنامه از ربات یا مرورگر، [دیپ‌لینک‌ها](deep-links.fa.md) را ببینید.

## قواعد قابل‌به‌روزرسانی: `autorouting`

در هدر پاسخ HTTP با نام `autorouting`، نشانی عمومی HTTPS فایل جداگانهٔ قواعد را بفرستید. دامنه باید واقعی و عمومی باشد؛ نشانی‌های نمونهٔ `.invalid` و آدرس‌های محلی پذیرفته نمی‌شوند.

```http
autorouting: https://rules.example.com/routing.json
```

منبع باید HTTP 200 و یک **شیء** JSON با UTF-8 و فیلدهای بالا برگرداند؛ نه Base64، نه لینک routing و نه JSON کامل Xray.

| شرط | رفتار پذیرفته‌شده |
| --- | --- |
| ساختار | فقط فیلدهای نمونه و `LastUpdated` اختیاری از نوع رشته؛ نام‌های جایگزین camelCase پشتیبانی می‌شوند. فیلد ناشناخته یا نام‌های جایگزین متناقض رد می‌شوند. |
| مقدارها | فهرست‌ها آرایهٔ رشته‌اند. `GlobalProxy` مقدار boolean JSON یا رشتهٔ `"true"` / `"false"` است. |
| اندازه | حداکثر 256 KiB برای فایل، 2048 ورودی در مجموع و 512 بایت برای هر ورودی. |
| نشانی | HTTPS روی پورت استاندارد، بدون اطلاعات کاربری و fragment. تعداد تغییرمسیرها محدود است و باید در همان origin بمانند. |
| حریم خصوصی درخواست | HWID، کوکی و توکن API لینک کاربر همراه درخواست قواعد ارسال نمی‌شود. |
| خطا | با خطای شبکه یا JSON نامعتبر، آخرین نسخهٔ سالم باقی می‌ماند. |
| محدوده | کش هر پروفایل کلید جداست؛ قواعد جدید در اتصال بعدی اعمال می‌شوند. |

| نسخهٔ مبنا | بررسی دوبارهٔ منبع سالم | مهلت درخواست |
| --- | --- | --- |
| iOS 2.2.0 | حداکثر یک بار در ساعت؛ پس از خطا با فاصله تکرار می‌شود | تا 12 ثانیه |
| Android APK 2.2.0 | 24 ساعت | 8 ثانیه |

اجرای پس‌زمینه به سیستم‌عامل وابسته است و زمان‌بندی دقیق تضمین نمی‌شود. این بازه‌ها با `profile-update-interval` که خود کلید را به‌روزرسانی می‌کند، متفاوت‌اند.

داخل پاسخ اشتراک، دستورهای `dodo://autorouting/add/…` و `dodo://autorouting/onadd/…` با منبع HTTPS هم شناخته می‌شوند. این‌ها دستورهای داخل پاسخ‌اند، نه لینک بازکردن برنامه از ربات یا مرورگر.

DNS/FakeDNS، منابع دلخواه `Geoipurl` / `Geositeurl` و `routeOrder` در این قالب **پشتیبانی نمی‌شوند**. برای ساختار پیچیده‌تر از پروفایل کامل و سازگار Xray استفاده کنید.

## JSON کامل Xray و متعادل‌کننده‌ها

پروفایل کاملِ سازگار همراه خروجی‌های وابسته، DNS، مسیریابی، balancerها و تنظیمات انتقال نگه‌داری می‌شود. پروفایل دارای balancer نباید به چند ردیف سرور مستقل تبدیل شود.

اعتبارسنجی ورود، ابزار تعمیر تنظیمات سرور نیست. برای واردشدن فایل، `fallbackTag` را حذف یا با `direct` جایگزین نکنید و balancer را کنار نگذارید. پذیرش هدف fallback ناموجود به ترکیب برنامه و هسته وابسته است؛ بارگذاری موفق به‌معنای کارکرد درست مسیر پشتیبان نیست. ارائه‌دهنده باید تگ خروجی‌ها و جابه‌جایی واقعی هنگام خرابی را بررسی کند.

دکمهٔ موقتاً پنهان «انتخاب خودکار» DoDo، balancer داخل JSON و سرویس آیندهٔ Auto از طریق API ارائه‌دهنده سه قابلیت متفاوت‌اند. پنهان‌شدن دکمه، balancer پروفایل را غیرفعال نمی‌کند. Auto مبتنی بر API هنوز عمومی نیست.

[قالب‌ها و یکپارچه‌سازی](integration.fa.md)، [پروتکل‌ها](protocols.fa.md) و [سازگاری](compatibility.fa.md) را ببینید.

## فایل‌های داخلی `geoip.dat` و `geosite.dat`

هر دو فایل در نسخه‌های مبنای iOS و Android وجود دارند و لازم نیست با اولین کلید دانلود شوند. منبع به‌روزرسانی [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) است.

پیش از نصب، SHA-256، ساختار فایل و دسته‌های لازم بررسی می‌شوند. در صورت خطا، آخرین جفت سالم حفظ می‌شود. ممکن است دسته‌های مجموعه‌های دیگر در این فایل‌ها نباشند؛ فایل دلخواه ارائه‌دهنده از طریق URL پشتیبانی نمی‌شود.

در iOS از مسیر **تنظیمات ← کاربران حرفه‌ای ← داده‌های جغرافیایی** نسخه‌ها را ببینید یا بررسی دستی انجام دهید. بررسی خودکار به زمان مجاز سیستم و دسترس‌پذیری منبع وابسته است. در Android، VPN فعال تا زمان قطع از فایل‌های انتخاب‌شده استفاده می‌کند؛ فایل جدید در اتصال بعدی اعمال می‌شود و امکان بازگشت به نسخهٔ سالم وجود دارد.

این فایل‌ها دسته‌های مسیریابی‌اند؛ نقشهٔ کاربران DoDo یا منبع آمار ارائه‌دهندگان نیستند.

## DNS، MTU و ترجیح IP

اگر مشکل مشخصی ندارید، تنظیمات پیش‌فرض را نگه دارید. تغییرات در اتصال بعدی اعمال می‌شوند و کلید ذخیره‌شده را بازنویسی نمی‌کنند.

| تنظیم | معنی و محدودیت |
| --- | --- |
| MTU تونل | پیش‌فرض/Auto، گزینه‌های 1420 / 1380 / 1280 یا عدد صحیح از 1280 تا 1500 بایت. اندازهٔ بسته است، نه سقف سرعت. جست‌وجوی خودکار بهترین MTU وجود ندارد. |
| ترجیح IP | «مطابق پیکربندی»، «ترجیح IPv4» یا «ترجیح IPv6» برای سروری با نام دامنه. این ترجیح است، نه خاموش‌کردن IPv6 دستگاه. در پروفایل پیچیده ممکن است رفتار ارائه‌دهنده حفظ شود. |
| DNS پروفایل | iOS در صورت امکانِ سازگارسازی امن، DNS تونل سیستم و Xray را هماهنگ می‌کند. ساختارهای مبهم، FakeDNS و وابستگی به DNS سیستم اجباری بازنویسی نمی‌شوند. Android نیز DNS ارائه‌دهنده را حفظ می‌کند، اما پیاده‌سازی تونل متفاوت است. |
| منابع VPN | در iOS با لاگ تشخیصی فعال و نشست تازه، حافظهٔ افزونه، Go heap، اتصال‌ها و file descriptorها نمایش داده می‌شوند. نبود داده به‌صورت مصرف صفر گزارش نمی‌شود. |

در شبکه‌های IPv6-only، DNS64 یا 464XLAT، انتخاب اجباری IPv4 راه‌حل همگانی نیست. شبکه و پروفایل واقعی را آزمایش کنید؛ ترجیح IP یا MTU کوچک‌تر سازگاری را تضمین نمی‌کند.

تنظیم دستی سقف حافظهٔ Xray، «No Limit Mode» و ویرایشگر همهٔ گزینه‌های هسته در این نسخهٔ مبنا وجود ندارند.
