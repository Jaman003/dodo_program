# Защищённые ссылки: DoDo crypt1 и AGE1

**crypt1 шифрует HTTPS-адрес пользователя. AGE1 шифрует тело ответа сервера.** Это независимые функции: одна не требует другой, платного тарифа или `providerid`.

В этой инструкции описана поддержка в iOS 2.2.0 и Android APK 2.2.0 (2107). На Android используйте буфер или ручной ввод: у плотных crypt1 QR-кодов есть известное ограничение сканирования на некоторых HUAWEI. Не считайте эту поддержку автоматически доступной в опубликованной macOS-версии; новый Mac-порт и Windows — отдельная работа. См. [совместимость](compatibility.ru.md).

## Начните без переделки панели

1. Возьмите действующий HTTPS-адрес конфигурации одного пользователя.
2. Откройте [генератор в браузере](https://dodoproxy.app/crypto/), вставьте адрес и оставьте автоматическую политику ответа.
3. Передайте полученную ссылку `dodoapp://crypt1/<JWE>` только этому пользователю.
4. Откройте её в DoDo, подтвердите добавление и проверьте число профилей, обновление и настоящее VPN-подключение.

Генератор использует WebCrypto локально: URL не отправляется в API шифрования и не сохраняется в cookies или хранилище браузера. Приложение расшифровывает контейнер локально и обращается к источнику только после подтверждения. **Для самой загрузки и обновления конфигурации по-прежнему нужны сеть и сервер провайдера.**

В Remnawave и собственной панели можно оставить прежний формат: список URI, Base64, полный Xray JSON или массив профилей. crypt1 оборачивает адрес, а не разбивает балансировщик на отдельные серверы и не заменяет парсер.

## Выдача ссылок из бота

Скачайте публичные [инструменты провайдера](https://dodoproxy.app/crypto/DoDo-crypt1-provider-tools.zip): CLI, модуль генератора, публичный манифест и спецификацию. Требуется Node.js 24+; SDK не требует npm-пакетов и не получает ключи из сети при генерации.

```sh
# Запускайте из распакованного каталога публичных инструментов.
# subscription-url.txt содержит HTTPS-адрес одного пользователя.
node cli/dodo-crypt1.mjs --name "Demo Provider" < subscription-url.txt

# Или передайте полный payload:
node cli/dodo-crypt1.mjs --input-json < payload.json
```

Не помещайте настоящий URL в аргументы команд, историю терминала и логи бота. Полученная защищённая ссылка тоже даёт доступ к конфигурации — это не материал для публичного поста.

```js
import { readFile } from 'node:fs/promises';
import { createCrypt1Link } from './generator/crypt1.mjs';

const publicManifest = JSON.parse(
  await readFile(new URL('./keys/public-keys.json', import.meta.url), 'utf8')
);

const link = await createCrypt1Link({
  v: 1,
  type: 'subscription-url',
  url: 'https://example.com/sub/demo-token?format=json',
  response: 'auto',
  name: 'Demo Provider',
}, publicManifest);

// Передайте link владельцу лично; не записывайте в общий лог.
```

`createCrypt1Link` возвращает `Promise<string>`. Берите `activeKid` из манифеста, а не фиксируйте один ID навсегда. Обновляйте локальную копию [публичного манифеста](https://dodoproxy.app/crypto/keys/public-keys.json) при ротации ключей DoDo, а не на каждом запросе пользователя. Закрытые ключи DoDo провайдеру не нужны.

## Поля payload

| Поле | Обязательно | Значение |
|---|---|---|
| `v` | Да | Число `1`. |
| `type` | Да | Строка `subscription-url`. |
| `url` | Да | Полный исходный HTTPS-адрес, до 4096 байт UTF-8. |
| `response` | Да | `auto` или `age1-required`; неявного значения при расшифровке нет. |
| `name` | Нет | Непустое имя без пробелов по краям, до 120 байт UTF-8, без управляющих/форматирующих символов. Не идентификатор провайдера. |

Весь сериализованный payload ограничен **8192 байтами UTF-8**, включая JSON-экранирование. Неизвестные поля, повторяющиеся JSON-имена и неверные типы отклоняются.

Нужно публично выглядящее DNS-имя и, при необходимости, порт 1–65535. Не принимаются логин/пароль в URL, фрагмент, пробелы и управляющие символы, обратная косая черта, IP-литералы, локальные имена и известные локальные IP-алиасы. Это синтаксическая проверка, а не доказательство публичности DNS-ответа. `example.com` выше — только пример, не рабочая конфигурация.

Не меняйте исходную строку URL: не декодируйте `%2F` и `%252F`, не заменяйте `+`, не переносите токен на другой host и не пересобирайте адрес нормализатором. См. [кодирование диплинков](deep-links.ru.md).

## Формат для собственной реализации

```text
dodoapp://crypt1/<protected>.<encrypted_key>.<iv>.<ciphertext>.<tag>
```

Нужна JWE Compact Serialization: ровно пять непустых сегментов, каждый — канонический Base64URL (`A–Z`, `a–z`, `0–9`, `-`, `_`) без `=`, пробелов, переносов и percent-encoding. В самой crypt1-ссылке не допускаются query, fragment и дополнительные сегменты пути. Максимум всей ссылки — **16 384 байта UTF-8**.

Защищённый заголовок содержит только четыре обязательных строковых поля:

```json
{"alg":"RSA-OAEP-256","enc":"A256GCM","typ":"dodo-subscription+jwe","kid":"<activeKid from the public manifest>"}
```

| Параметр | Требование |
|---|---|
| RSA | 3072 бита, exponent 65537. |
| Шифрование ключа | RSA-OAEP-256; SHA-256 и MGF1 SHA-256; пустой label. |
| CEK | Новые случайные 32 байта для каждой ссылки. |
| Шифрование содержимого | AES-256-GCM; новый IV 12 байт; authentication tag 16 байт. |
| AAD | ASCII-байты первого **закодированного** сегмента JWE. |
| Шифрованный ключ | 384 байта. |

Не поддерживаются `zip`, `crit`, встроенные ключи и URL загрузки ключей. Неизвестный `kid` завершается локальной ошибкой — ключи по адресу из JWE-заголовка не скачиваются. Повторяющиеся JSON-имена, в том числе эквивалентные через escape, запрещены. На JVM задавайте MGF1 SHA-256 явно: одного имени шифра недостаточно для всех криптопровайдеров.

Повторная генерация для того же URL создаёт другой шифротекст. DoDo сопоставляет проверенный исходный источник, а не создаёт новую карточку на каждый случайный контейнер. При копировании и отправке QR используется исходная crypt1-ссылка, а не раскрытый URL. Длинная ссылка может не поместиться в QR — оставляйте текстовый способ отправки.

## AGE1: отдельное шифрование ответа сервера

AGE1 использует age file format v1 и **X25519 recipients**, не RSA-ключ crypt1. Получателя DoDo берите из `ageRecipients` публичного манифеста.

| Политика внутри crypt1 | Принимаемый ответ |
|---|---|
| `auto` | Поддерживаемый открытый ответ или корректный AGE1. Распознанный повреждённый AGE не разбирается повторно как текст. |
| `age1-required` | Корректный AGE1 при каждой загрузке, включая резерв. Открытый ответ отклоняется. |

`age1-required` **не включает** шифрование на сервере. Сначала настройте источник, затем выдавайте ссылки с этой политикой. DoDo не отправляет специальный заголовок для включения AGE: `response` — локальное правило приёма, а не команда серверу. Самая понятная схема — отдельный HTTPS-адрес, всегда возвращающий AGE1.

Пример с официальным CLI `age` и `jq`:

```sh
jq -er '.ageRecipients[0].recipient' keys/public-keys.json > age-recipients.txt

age --encrypt --recipients-file age-recipients.txt \
  --output subscription.json.age subscription.json

# Альтернатива: ASCII armor вместо бинарного тела.
age --encrypt --armor --recipients-file age-recipients.txt \
  --output subscription.json.age.armor subscription.json
```

Верните файл непосредственно телом HTTP-ответа. Для бинарного age v1 обычно используется `application/octet-stream`, для ASCII armor — `text/plain`. Распознавание идёт по началу тела, а не только по Content-Type. Не добавляйте JSON-обёртку, дополнительный Base64, BOM и HTML.

Метаданные остаются настоящими HTTP-заголовками вне зашифрованного тела:

```http
HTTP/1.1 200 OK
Content-Type: application/octet-stream
Cache-Control: private, no-store
profile-title: Demo Provider
profile-update-interval: 2
providerid: demo-vpn
fallback-url: https://backup.example.com/sub/demo-token
```

Поддерживаются бинарный `age-encryption.org/v1` и ASCII armor `-----BEGIN AGE ENCRYPTED FILE-----`. Не поддерживаются парольный scrypt, SSH, плагины и файлы только для чужого получателя. Лимит зашифрованного AGE-тела — **2 MiB**; также действуют общие пределы времени, размеров и попыток загрузчика. В описанной мобильной базе операция ограничена 25 секундами; предел ответа/операции на iOS — 8 000 000 / 12 000 000 байт, на Android — 2 / 4 MiB. Один JSON-профиль iOS ограничен 2 000 000 байтами.

При `age1-required` и основной, и [резервный](fallback.ru.md) адрес должны отдавать AGE1. Ошибку целостности, ключа или формата нельзя обходить извлечением отдельных URI из неудачного ответа.

## Безопасность и проверка

crypt1 — **не DRM и не доказательство личности провайдера**. При целенаправленном исследовании доверенного приложения можно извлечь данные для расшифровки. Исходный URL и защищённая ссылка остаются секретами. HTTPS, авторизация, отзыв доступа и лимиты устройств должны сохраняться на сервере; административные токены и пароли сервера внутрь не помещайте.

- Проверьте полные профили и балансировщики без изменения их смысла.
- Проверьте неверного получателя, повреждённую ссылку/тело и неизвестный ID ключа: нужен отказ.
- Убедитесь, что `age1-required` отклоняет открытый ответ, в том числе резервный.
- Проверьте повторный импорт, обновление и отправку. Неудачное обновление не должно удалять рабочую конфигурацию.
- Проверяйте реальный VPN-трафик отдельно от успешной расшифровки и импорта.

DoDo crypt1/AGE1 **не расшифровывает** закрытые форматы Happ и INCY. Совместимый HTTP/JSON-ответ — другая функция.
