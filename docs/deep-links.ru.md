# Диплинки для ботов и сайтов

Используйте `dodoapp://import?url=…`, чтобы открыть DoDo и предложить добавить конфигурацию пользователя. Диплинк не авторизует пользователя и не создаёт доступ к VPN: ваш сервис должен заранее выдать ему действующую ссылку.

Примеры ниже относятся к iOS 2.2.0 и Android APK 2.2.0 (2107). Не переносите поддержку всех команд автоматически на macOS и Windows — смотрите [совместимость платформ](compatibility.ru.md).

## Рекомендуемая ссылка импорта

```text
dodoapp://import?url=https%3A%2F%2Fexample.com%2Fsub%2Fdemo-token
```

Исходный адрес в примере — `https://example.com/sub/demo-token`. Это заглушка, а не рабочий ключ.

| Форма | Назначение |
|---|---|
| `dodoapp://import?url=…` | Основная команда импорта. |
| `dodoapp://import-sub?url=…` | Поддерживаемый алиас импорта. |
| `link` вместо `url` | Алиас параметра; нужен ровно один непустой целевой параметр. |
| `dodoapp://crypt1/<JWE>` | Защищённая ссылка DoDo — см. [crypt1 и AGE1](crypto.ru.md). |

Для интеграции передавайте полный HTTPS-адрес. Не добавляйте одновременно конфликтующие `url` и `link`, два одинаковых параметра или другую команду приложения вместо адреса конфигурации.

## Один слой кодирования на каждую обёртку

Считайте исходный URL непрозрачной строкой. Кодируйте его один раз при помещении в query-параметр диплинка. Не декодируйте и не пересобирайте путь, токен, `%2F`, `%252F`, `+` и параметры исходного адреса.

```js
const source = 'https://example.com/sub/demo-token?format=json&value=a%2Fb+test';
const deepLink = `dodoapp://import?url=${encodeURIComponent(source)}`;

// Только если ваша HTTPS-страница принимает диплинк в параметре url:
const landingLink = `https://example.com/connect?url=${encodeURIComponent(deepLink)}`;
```

Вторая строка добавляет слой для диплинка. Последняя — отдельный слой для внешней веб-ссылки. Страница перехода должна снять только свой слой, а затем открыть диплинк. Многократное декодирование всей строки может изменить ключ пользователя.

Не используйте обработку `application/x-www-form-urlencoded`, превращающую неэкранированный `+` в пробел. `encodeURIComponent` кодирует сам знак плюса как `%2B`.

## Старые и неподдерживаемые формы

| Форма | Как поступить |
|---|---|
| `dodoapp://add/<URL>` | Не используйте: команда `add` не является документированным импортом. |
| `dodoapp://import/<URL>` | Не используйте адрес в пути. Замените на `import?url=` с однократным кодированием. |
| `dodo://import…` | Импорт конфигурации не поддерживается. Схема `dodo` используется для команд маршрутизации ниже. |
| `happ://…`, включая `happ://crypto…` | Это не команды DoDo. Временная совместимость HTTP/JSON не означает поддержку схемы другого приложения или расшифровку его закрытого формата. |

В словаре клиентов бота оставьте один шаблон `dodo`: при двух одинаковых ключах одна запись может перезаписать другую.

## Маршрутизация — отдельная команда

```text
dodo://routing/add/<BASE64URL_UTF8_JSON>
dodo://routing/onadd/<BASE64URL_UTF8_JSON>
dodo://routing/off
```

Для этих команд также принимается схема `dodoapp`. Внутри нужен **профиль правил DoDo**, а не полная конфигурация Xray. Для пути удобен Base64URL без завершающих `=`; обычный Base64 требует своего однократного percent-encoding.

Добавленный профиль применяется при следующем подключении. Команда `off` отключает его применение, но не удаляет сам профиль. Поля правил, обновление и ограничения платформ описаны в разделе [Маршрутизация и геоданные](routing.ru.md).

## Команды VPN отличаются на платформах

| Команда | iOS | Android APK 2.2.0 |
|---|---|---|
| `dodoapp://toggle-vpn` | Переключает состояние VPN. Повторное открытие переключит обратно. | Недоступна. |
| `dodoapp://vpn-permission` | Показывает объяснение; не обходит и не открывает автоматически системный диалог Apple. | Открывает сценарий объяснения и запроса разрешения VPN в Android. |
| `dodoapp://vpn-disclosure` | Алиас команды объяснения. | Сценарий раскрытия информации и разрешения Android. |

Переключатель — не команда «включить». Не повторяйте его автоматически при загрузке страницы или по таймауту.

## Проверка перед выдачей пользователям

1. Установите DoDo и откройте рекомендуемый диплинк из того же браузера или мессенджера, которым пользуются ваши абоненты.
2. Проверьте адрес с query-параметрами, `%`-последовательностями и `+`, не меняя исходную строку.
3. Сравните число профилей и метаданные, проверьте обновление и настоящее VPN-подключение: одно открытие приложения не проверяет туннель.
4. Проверьте отмену и повторное открытие. Не записывайте реальные ключи и crypt1-ссылки в логи.

DoDo должен быть уже установлен. Установка через App Store или Google Play не сохраняет команду импорта автоматически — после установки нужно открыть исходную ссылку ещё раз. Сам диплинк не определяет аккаунт Telegram. Буфер обмена читается по действию пользователя, без скрытого перехвата.

Длинная crypt1-ссылка может дать слишком плотный QR-код. На некоторых HUAWEI у Android есть известное ограничение его распознавания — оставляйте также копирование текста и ручной ввод.
