# اتصال سرویس ارائه‌دهنده

یک نشانی HTTPS برای پیکربندی و دکمهٔ [«باز کردن در DoDo»](deep-links.fa.md) به کاربران بدهید. واردکردن معمولی و اتصال VPN به حساب DoDo، توکن API یا پنل خاصی نیاز ندارد. Remnawave، 3x-ui و سرویس اختصاصی شما می‌توانند قالب‌های پشتیبانی‌شده را ارائه کنند.

این راهنما بر قابلیت‌های iOS 2.2.0 و Android APK 2.2.0 (2107) تکیه دارد. تفاوت نسخه‌ها در [جدول سازگاری](compatibility.fa.md) آمده است.

**در بیلد آماده‌شدهٔ iOS 2.2.2 (113):** فیلدهای ریشهٔ `env` و `version` در JSON کامل حفظ می‌شوند و هسته `version.min` / `version.max` را پیش از اجرا بررسی می‌کند. پارامترهای سازگار URI و هدر واقعی پاسخ موفق HTTP می‌توانند FinalMask / قطعه‌بندی را تعیین کنند. بیلد برای پردازش در App Store Connect بارگذاری شده، اما هنوز به App Review ارسال نشده و عرضهٔ فروشگاهی اعلام نشده است. [پارامترها، اولویت و محدودیت‌ها](ios-2.2.2.fa.md). این تغییرات خودکار شامل Android نمی‌شوند.

## ۱. پاسخ درست را ارائه کنید

در iOS مقدار `User-Agent: DoDoApp` است. Android از پیشوند `DoDoApp/` استفاده می‌کند؛ برای نمونه `DoDoApp/2.2.0+2107 (Android 15; Demo Model)`. شرط برابری دقیق با `DoDoApp`، Android را پوشش نمی‌دهد.

پاسخ HTTP 200 و بدنهٔ کامل یک قالب پشتیبانی‌شده را بفرستید. برای JSON از `application/json` استفاده کنید. نمونهٔ زیر آزمایشی است و کار نمی‌کند:

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
profile-title: Demo Provider
profile-update-interval: 1
support-url: https://example.invalid/support

vless://00000000-0000-4000-8000-000000000001@example.invalid:443?security=tls&type=ws&path=%2Fdemo#Demo
```

| بدنه | رفتار DoDo |
| --- | --- |
| فهرست URI | سرورهای مستقل، معمولاً یک مورد در هر خط |
| Base64 | فهرست یا ظرف JSON سازگار؛ Base64 رمزنگاری نیست |
| Xray JSON کامل | یک پروفایل با DNS، مسیریابی، متعادل‌کننده‌ها و وابستگی خروجی‌ها |
| آرایهٔ پروفایل‌های JSON کامل | هر پیکربندی مستقل یک گزینه است |
| مجموعهٔ outbounds مستقل | سرورهای جدا، بدون ساختن متعادل‌کنندهٔ مصنوعی |

پروفایل زنجیره‌ای یا متعادل‌شده را به لینک‌های مجزا تبدیل نکنید. DoDo برچسب‌ها، وابستگی‌ها و تنظیمات سازگار `observatory`، `burstObservatory`، `policy` و `stats` را نگه می‌دارد. ورودی‌های داخلی و پورت‌های محلی ممکن است هنگام اجرا تنظیم شوند؛ سازگاری به هسته هم وابسته است.

پروفایل نامعتبر یا پشتیبانی‌نشده رد می‌شود، نه اینکه پنهانی ساده شود. شکست به‌روزرسانی، فهرست قبلی را حذف نمی‌کند. شناسه، ترتیب، سنجاق، انتخاب و آخرین پینگ سرورهای منطبق حفظ می‌شوند.

### سازگاری موقت با پاسخ JSON مربوط به Happ

درخواست نخست به نشانی عادی فرستاده می‌شود. اگر پاسخ JSON کامل و قابل استفاده باشد، درخواست اضافه‌ای نیست. در غیر این صورت ممکن است **همان URL** با `User-Agent: Happ/DoDoApp-compat` و سرآیند `X-DoDo-Client` که DoDo را معرفی می‌کند دوباره درخواست شود. پاسخ‌ها با هم ادغام نمی‌شوند.

بهتر است در پنل، قانون DoDo یا لینک صریح قالب کامل بدهید. برنامه خودسرانه `/json` اضافه نمی‌کند. شکست تلاش سازگاری پاسخ اصلی قابل استفاده را از بین نمی‌برد؛ پروفایل کامل ذخیره‌شده هم با فهرست ناقص URI جایگزین نمی‌شود. این قابلیت به معنی پشتیبانی از دیپ‌لینک یا رمزنگاری خصوصی Happ نیست.

## ۲. اطلاعات کارت را اضافه کنید

این فیلدها سرآیند پاسخ HTTP هستند. بزرگی حروف نام سرآیند مهم نیست.

| سرآیند | مقدار و کاربرد |
| --- | --- |
| `profile-title` | نام سرویس، متن یا UTF-8 با `base64:`؛ جایگزین‌ها: `subscription-name` و سپس filename / filename* در `Content-Disposition` |
| `x-dodo-provider-logo-url` | نشانی عمومی HTTPS لوگوی سرویس، نه آیکون برنامه |
| `support-url` | صفحه یا ربات پشتیبانی؛ دکمهٔ پشتیبانی در صورت وجود نمایش داده می‌شود |
| `profile-web-page-url` | حساب، ربات یا تمدید؛ نام جایگزین `homepage`؛ پرداخت در سرویس شما انجام می‌شود |
| `subscription-userinfo` | `upload=…; download=…; total=…; expire=…`؛ حجم به بایت و انقضا به ثانیهٔ Unix |
| `profile-update-interval` | عدد صحیح **ساعت** از ۱ تا ۱۶۸، پیش‌فرض یک ساعت؛ اجرای پس‌زمینه را سیستم‌عامل زمان‌بندی می‌کند |
| `announce` | متن یا `base64:` سازگار برای اطلاعیهٔ کارت، نه پوش یا استوری |
| `routing` / `autorouting` | [قواعد مسیریابی](routing.fa.md) ثابت یا قابل به‌روزرسانی |
| `fallback-url` / `providerid` | [نشانی پشتیبان](fallback.fa.md) از پیش اعلام‌شده و شناسهٔ تطبیق آن |
| `x-dodo-provider-id` | UUID عمومی ارائه‌دهنده برای [اتصال پنل](provider-console.fa.md) |

برای فرادادهٔ عادی ابتدا سرآیند واقعی، سپس توضیحات پشتیبانی‌شدهٔ بدنه، Base64 بازشده و فرادادهٔ JSON خوانده می‌شود؛ نخستین مقدار معتبر استفاده می‌شود. فایل ثابت می‌تواند خطوطی مانند `#profile-title: Demo Provider` داشته باشد.

**استثنا:** `x-dodo-provider-id` فقط از پاسخ موفق HTTPS روی میزبان دقیقاً تأییدشده پذیرفته می‌شود، نه توضیح بدنه. آن را با برچسب قدیمی `providerid` برای نشانی پشتیبان اشتباه نگیرید. هیچ‌کدام پرداخت یا مالکیت کلید را ثابت نمی‌کنند.

توکن محرمانهٔ کاربر را در نشانی عمومی لوگو یا پشتیبانی نگذارید. HTTP 403 به‌تنهایی تاریخ انقضا را تعیین نمی‌کند.

## ۳. محدودیت دستگاه را در سرور خود بررسی کنید

درخواست پیکربندی شامل شناسهٔ نصب و اطلاعات دستگاه است:

```http
User-Agent: DoDoApp
Accept: */*
x-hwid: 00000000-0000-4000-8000-000000000001
x-device-os: iOS
x-ver-os: 18.5.0
x-device-model: iPhone 14 Pro
```

Android همین نام‌های سرآیند را با مدل، نسخهٔ سیستم، نام Android و User-Agent نسخه‌دار خودش می‌فرستد. HWID شماره‌سریال یا IDFA نیست و با تلاش مجدد عوض نمی‌شود. بازنشانی تنظیمات برنامه سهمیهٔ دستگاه نزد ارائه‌دهنده را بازنشانی نمی‌کند. شناسه فقط در سرآیند فرستاده می‌شود، نه URL.

| پاسخ ارائه‌دهنده | نتیجه |
| --- | --- |
| `x-hwid-max-devices-reached: true` | خطای رسیدن به سقف دستگاه |
| `x-hwid-limit: true` | علامت قدیمی همان محدودیت |
| `x-hwid-not-supported: true` یا `HWID_REQUIRED` صریح | خطای روشن بارگیری بدون ساخت شناسهٔ جدید |

مجوز دسترسی و تعداد دستگاه را سرور ارائه‌دهنده تعیین می‌کند؛ HWID جای احراز هویت نیست. در تغییر origin، iOS سرآیندهای حساس را حذف و Android تغییر مسیر را رد می‌کند. تنزل HTTPS به HTTP مجاز نیست.

## محدودیت‌ها و آزمایش پیش از انتشار

| محدودیت | iOS | Android APK |
| --- | --- | --- |
| هر پاسخ | 8,000,000 بایت | 2 MiB |
| کل عملیات | 12,000,000 بایت | 4 MiB |
| هر پروفایل JSON | 2,000,000 بایت | در سقف پاسخ |
| بدنهٔ رمز‌شدهٔ AGE1 | 2 MiB | 2 MiB |
| زمان کل بارگیری | ۲۵ ثانیه، تلاش محدود | ۲۵ ثانیه، تلاش محدود |

اعتبارسنجی TLS برای نجات بارگیری خاموش نمی‌شود و پاسخ ناقص همراه خطای شبکه وارد نمی‌شود.

پیش از ارائهٔ دکمه به کاربران، واردکردن، به‌روزرسانی، تعداد و ترتیب پروفایل‌ها، حجم و انقضا، خطای سقف دستگاه و یک اتصال واقعی را روی هر پلتفرم هدف امتحان کنید. پارامترهای واقعی پنل خود را به کار ببرید؛ واردکردن موفق یا پینگ TCP، دسترسی سالم به اینترنت را ثابت نمی‌کند.
