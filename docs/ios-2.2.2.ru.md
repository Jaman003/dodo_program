**Статус на 12 ноября 2026 года:** сборка **iOS 2.2.2 (113)** загружена в App Store Connect для обработки. Она ещё не отправлена в App Review и пока не объявлена доступной в App Store. Обработка, проверка Apple и публикация — разные этапы.

Изменения ниже относятся только к этой iOS-сборке. Минимальная версия — iOS 15; ядро остаётся Xray 26.10.31. Они не означают обновление Android APK 2.2.0 (2107), macOS или Windows.

## Полный JSON: `env` и `version`

Корневые поля `env` и `version` сохраняются вместе с полным профилем. Даже документ с одними `outbounds` и этими полями больше не превращается в набор отдельных ссылок. Обычная коллекция независимых выходов без признаков полного профиля остаётся коллекцией.

Требования `version.min` / `version.max` проверяются закреплённым ядром до запуска. Несовместимое требование не игнорируется. Поддерживаемые переменные `env` применяются для конкретного служебного ядра или подключения и восстанавливаются после подтверждённого завершения; настройки одного сервиса не должны переходить в следующий сеанс. Пути ресурсов, параметры приложения, Go/TUN, proxy и доверия TLS защищены от подмены. Неподдерживаемое активное требование отклоняется явно, без публикации значений ENV в ошибке.

## HTTP GET / HEAD через профиль

Подключение и HTTP-проверка используют общую подготовку конфигурации: выбранный прокси или балансировщик, зависимости выходов, DNS, маршруты, транспортные параметры и область геоданных. Проверка работает в изолированном служебном экземпляре Xray и не переподключает текущий VPN. Неуспешный HTTP-запрос не заменяется успешным прямым соединением или открытым TCP-портом.

Для Hysteria2 исправлена подготовка геоданных при HTTP-проверке. Поскольку это UDP-протокол, в TCP-режиме для таких профилей по-прежнему автоматически применяется HTTP. Обычный TCP показывает исходное измеренное время без деления; только оценочный DoDo Ping делит HTTP GET на 3,3. Это не тест скорости и не полная проверка работающего VPN-туннеля.

## DNS, раздельный DoH и ограниченный FakeDNS

Доработано согласование DNS Xray с системным туннелем, раздельный DoH и локальные DNS-алиасы. Цепочки алиасов ограничены и проверяются на циклы. Неоднозначная схема не переписывается принудительно ради запуска.

Поддерживаются совместимые, явно заданные провайдером FakeDNS-профили со стандартными пулами. Это не универсальная поддержка произвольных пулов, смешанных DNS-схем или Lua. Для FakeDNS-профиля отдельный HTTP-замер недоступен; `N/A` в такой проверке само по себе не означает, что VPN не работает.

## FinalMask и параметры фрагментации

В совместимых URI распознаются `fm`, `fragment` и `fragmentPackets` / `fragmentLength` / `fragmentInterval`. Из реального успешного HTTP-ответа поддерживаются:

```http
fragmentation-enable: true
fragmentation-type: xray
fragmentation-packets: tlshello
fragmentation-length: 50-100
fragmentation-delay: 10-20
fragmentation-maxsplit: 100-200
```

`fragmentation-interval` допускается как альтернативное имя HTTP-заголовка задержки. Это не правило переименования полей внутри готового JSON. Маска из заголовков включается только при `fragmentation-enable: true` и типе `xray`.

Приоритет: **готовый полный JSON → явная маска URI → заголовки ответа**. Две маски автоматически не складываются. Полный JSON провайдера не исправляется молча; неподдерживаемый активный режим отклоняется. Автоматическая TCP-фрагментация не накладывается на UDP-only / Hysteria. Отдельного редактора всех параметров маски в интерфейсе нет.

## Что остаётся без изменений

Исправные ключи, порядок профилей и параметры серверов не нужно менять ради обновления клиента. Проверка сертификатов TLS не ослабляется, новых SDK нет. Правильный импорт или успешная проверка одного URL не гарантируют работу всех узлов и операторов; провайдеру по-прежнему нужно проверять свои DNS, теги и транспортные параметры.
