# Маршрутизация, геоданные и настройки сети

Правила определяют, какие адреса открывать напрямую, направлять через прокси или блокировать. Небольшой формат правил DoDo — не полный Xray JSON. Не помещайте конфигурацию Xray целиком в поля этого формата.

Справочная база этой страницы — iOS 2.2.0 и Android APK 2.2.0 (2107). Возможности другой сборки нужно проверять отдельно.

## Статические правила

```json
{
  "Name": "Demo rules",
  "GlobalProxy": true,
  "DomainStrategy": "IPIfNonMatch",
  "DirectSites": ["domain:example.invalid"],
  "DirectIp": [],
  "ProxySites": ["full:proxy.example.invalid"],
  "ProxyIp": [],
  "BlockSites": ["geosite:category-ads-all"],
  "BlockIp": []
}
```

| Поле | Назначение |
| --- | --- |
| `Name` | Название профиля правил. |
| `GlobalProxy` | Настройка глобального прокси для этого профиля правил. |
| `DomainStrategy` | Стратегия разрешения доменов. Удалённый формат принимает `AsIs`, `IPIfNonMatch` и `IPOnDemand`. |
| `DirectSites` / `DirectIp` | Адреса для прямого подключения. |
| `ProxySites` / `ProxyIp` | Адреса для прокси. |
| `BlockSites` / `BlockIp` | Адреса для блокировки. |

В доменных списках допустимы домены и поддерживаемые записи `domain:`, `full:`, проверяемый `regexp:` и `geosite:`. В IP-списках — IP-адреса, сети CIDR и `geoip:`. Указанные категории должны существовать в доступных геофайлах.

### Добавление локального профиля

Закодируйте JSON в UTF-8 через Base64 или Base64URL. Для ссылки удобнее Base64URL без завершающих `=`; обычный Base64 можно один раз обработать percent-encoding.

```text
dodo://routing/add/{BASE64_UTF8_JSON}
dodo://routing/onadd/{BASE64_UTF8_JSON}
dodo://routing/off
```

`add` и `onadd` сохраняют и включают профиль. `off` отключает его без удаления. Не добавляйте имя пользователя, пароль, порт, query или fragment. Правила применяются при следующем подключении; работающий VPN сам не переподключается.

Открытие приложения из бота или браузера описано в разделе [диплинков](deep-links.ru.md).

## Обновляемые правила: `autorouting`

В HTTP-заголовке ответа `autorouting` передайте публичный HTTPS-адрес отдельного файла правил. Нужен настоящий публичный домен: пример `.invalid` и локальные адреса не принимаются.

```http
autorouting: https://rules.example.com/routing.json
```

Источник должен вернуть HTTP 200 и UTF-8 JSON-**объект** с полями из примера. Не Base64, не routing-ссылку и не полный Xray JSON.

| Требование | Что принимается |
| --- | --- |
| Схема | Только поля примера и необязательный строковый `LastUpdated`; поддерживаются camelCase-алиасы. Неизвестные поля и конфликтующие алиасы отклоняются. |
| Значения | Списки — массивы строк. `GlobalProxy` — JSON boolean либо строка `"true"` / `"false"`. |
| Размер | До 256 KiB на файл, до 2048 записей суммарно, до 512 байт на запись. |
| Адрес | HTTPS на стандартном порту, без имени пользователя, пароля и fragment. Редиректы ограничены и разрешены только в пределах одного origin. |
| Приватность запроса | HWID, cookies и API-токены ключа не передаются в запрос правил. |
| Ошибка | При сбое сети или неверном JSON остаётся последняя рабочая версия. |
| Область действия | Кеш отдельный для каждого ключа; новые правила применяются при следующем подключении. |

| Справочная версия | Повторная проверка успешного источника | Таймаут запроса |
| --- | --- | --- |
| iOS 2.2.0 | Не чаще раза в час; после ошибки — пауза перед повтором | До 12 секунд |
| Android APK 2.2.0 | 24 часа | 8 секунд |

Время работы в фоне определяет ОС: точное расписание не гарантируется. Эти интервалы не связаны с `profile-update-interval`, который обновляет сам ключ.

В теле подписки также распознаются `dodo://autorouting/add/…` и `dodo://autorouting/onadd/…` с HTTPS-источником. Это команды внутри ответа, а не ссылки для запуска приложения из бота или браузера.

DNS/FakeDNS, произвольные источники `Geoipurl` / `Geositeurl` и `routeOrder` в этом формате **не поддерживаются**. Для сложной схемы используйте совместимый полный Xray JSON.

## Полный Xray JSON и балансировщики

Совместимый полный профиль сохраняется вместе со связанными выходами, DNS, маршрутами, балансировщиками и параметрами транспорта. Профиль с балансировщиком не должен превращаться в несколько независимых строк серверов.

Проверка импорта не исправляет настройки сервера. Не удаляйте `fallbackTag`, не заменяйте его на `direct` и не убирайте балансировщик ради успешного добавления. Допустимость отсутствующего резервного выхода зависит от сочетания клиента и ядра; успешная загрузка ещё не доказывает работу резерва. Провайдеру нужно проверить теги выходов и реальное переключение при отказе.

Временно скрытая кнопка «Автовыбор» DoDo, балансировщик внутри Xray JSON и будущий Auto через API провайдера — разные функции. Скрытие кнопки не отключает балансировщик полного профиля. Auto через API пока не доступен для общего подключения.

См. [форматы и интеграцию](integration.ru.md), [протоколы](protocols.ru.md) и [совместимость](compatibility.ru.md).

## Встроенные `geoip.dat` и `geosite.dat`

Оба файла встроены в указанные версии iOS и Android. Скачивать их вместе с первым ключом не требуется. Источник обновлений — [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat).

Перед установкой проверяются SHA-256, формат и нужные категории. При ошибке остаётся рабочая пара. Категории из другого набора могут отсутствовать; произвольные геофайлы провайдера по URL не поддерживаются.

В iOS версии и ручная проверка находятся в **Настройки → Для опытных пользователей → Геоданные**. Автопроверка выполняется, когда ОС даёт время, а источник доступен. В Android работающий VPN использует выбранные файлы до отключения; новая версия применяется при следующем подключении, предусмотрен откат к рабочей.

Это категории маршрутизации, не карта пользователей DoDo и не источник аналитики провайдеров.

## DNS, MTU и предпочтительный IP

Без конкретной проблемы оставляйте стандартные значения. Изменения действуют при следующем подключении и не переписывают сохранённый ключ.

| Параметр | Значение и ограничения |
| --- | --- |
| MTU туннеля | По умолчанию/Auto, варианты 1420 / 1380 / 1280 либо целое число от 1280 до 1500 байт. Это размер пакета, не лимит скорости. Автоматического поиска лучшего MTU нет. |
| Предпочтительный IP | «Как в конфигурации», «Предпочитать IPv4» или «Предпочитать IPv6» для сервера с доменным именем. Это предпочтение, а не отключение IPv6 на телефоне. Сложный профиль может сохранить поведение провайдера. |
| DNS из профиля | iOS согласует DNS системного туннеля с Xray, когда возможна безопасная адаптация. Неоднозначные схемы, FakeDNS и зависимости от системного DNS принудительно не переписываются. Android также сохраняет DNS провайдера, но устройство туннеля отличается. |
| Ресурсы VPN | В iOS отдельный экран показывает память расширения, Go heap, соединения и файловые дескрипторы при включённых диагностических логах и свежем сеансе. Нет данных — не означает нулевое потребление. |

Для IPv6-only, DNS64 и 464XLAT принудительный выбор только IPv4 не универсальное решение. Проверяйте сеть и профиль: ни выбор IP, ни уменьшение MTU не гарантируют совместимость.

Ручной ползунок лимита памяти Xray, No Limit Mode и редактор всех параметров ядра в эту справочную версию не входят.
