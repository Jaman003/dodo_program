# Интеграция для провайдеров

Выдайте пользователю HTTPS-ссылку на конфигурацию и кнопку [«Открыть в DoDo»](deep-links.ru.md). Для обычного импорта и подключения не нужны аккаунт DoDo, API-токен или определённая панель. Подойдут Remnawave, 3x-ui и собственный сервис с поддерживаемым форматом ответа.

Ниже описаны возможности iOS 2.2.0 и Android APK 2.2.0 (2107). Различия между платформами и статус выпуска — в [таблице совместимости](compatibility.ru.md).

**Для подготовленной iOS 2.2.2 (113):** корневые `env` и `version` сохраняются в полном JSON; требования `version.min` / `version.max` проверяются ядром до запуска. Добавлена совместимость параметров FinalMask / фрагментации из URI и реальных успешных HTTP-заголовков. Сборка загружена в App Store Connect для обработки, но ещё не отправлена в App Review и не объявлена доступной в магазине. [Параметры, приоритеты и ограничения](ios-2.2.2.ru.md). Эти изменения не переносятся автоматически на Android.

## 1. Настройте выдачу конфигураций

iOS отправляет `User-Agent: DoDoApp`. В Android используется префикс `DoDoApp/`, например `DoDoApp/2.2.0+2107 (Android 15; Demo Model)`. Правило с точным равенством `DoDoApp` не охватит Android.

Верните HTTP 200 с полным телом поддерживаемого формата. Для JSON используйте `application/json`. Ниже пример текстового ответа; адреса и ключ вымышленные:

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
profile-title: Demo Provider
profile-update-interval: 1
support-url: https://example.invalid/support

vless://00000000-0000-4000-8000-000000000001@example.invalid:443?security=tls&type=ws&path=%2Fdemo#Demo
```

| Тело ответа | Как его читает DoDo |
| --- | --- |
| Список URI | Независимые серверы, обычно по одному на строку |
| Base64 | Поддерживаемый кодированный список или JSON-контейнер; это не шифрование |
| Полный Xray JSON | Один профиль со своими DNS, маршрутизацией, балансировщиками и зависимостями выходов |
| Массив полных JSON-профилей | Каждая самостоятельная конфигурация — отдельный вариант выбора |
| Коллекция независимых outbounds | Отдельные серверы без искусственного балансировщика |

Не разбивайте балансируемый или каскадный профиль на отдельные ссылки. DoDo сохраняет совместимые теги, связи, `observatory`, `burstObservatory`, `policy` и `stats`. Служебные inbound и локальные порты могут адаптироваться при запуске. Возможности зависят и от встроенного ядра.

Повреждённый или неподдерживаемый профиль отклоняется, а не упрощается незаметно. При неудачном обновлении прежние серверы остаются. У совпадающих серверов сохраняются ID, порядок, закрепление, выбор и последние значения пинга.

### Временная совместимость JSON-выдачи Happ

Сначала DoDo запрашивает обычный URL. Если ответ уже содержит полный пригодный JSON, дополнительного запроса нет. Иначе возможен повтор **того же URL** с `User-Agent: Happ/DoDoApp-compat` и заголовком `X-DoDo-Client`, обозначающим настоящий клиент. Ответы не объединяются.

Лучше добавить правило выдачи DoDo или предоставить явную ссылку полного формата из вашей панели. Приложение не дописывает `/json` к произвольным адресам. При неудаче совместимого запроса пригодный основной ответ сохраняется; уже сохранённый полный профиль не заменяется неполным списком URI. Это совместимость формата ответа, **не** поддержка диплинков Happ или его закрытого шифрования.

## 2. Передайте данные карточки

Отправляйте их в заголовках HTTP-ответа. Регистр имён не важен.

| Заголовок | Значение и результат |
| --- | --- |
| `profile-title` | Название сервиса текстом или `base64:` UTF-8. Запасные поля: `subscription-name`, затем filename / filename* из `Content-Disposition` |
| `x-dodo-provider-logo-url` | Публичный HTTPS-адрес логотипа сервиса; иконку приложения не меняет |
| `support-url` | Поддержка или бот; при наличии появляется кнопка «Поддержка» |
| `profile-web-page-url` | Кабинет, бот или страница продления; алиас `homepage`. Оплата остаётся на стороне вашего сервиса |
| `subscription-userinfo` | `upload=…; download=…; total=…; expire=…`; объёмы в байтах, срок — Unix timestamp в секундах |
| `profile-update-interval` | Целое число **часов** от 1 до 168; по умолчанию 1 час. Выполнение в фоне планирует ОС |
| `announce` | Текст или поддерживаемый `base64:` для объявления в карточке; не push и не сторис |
| `routing` / `autorouting` | Статические или обновляемые [правила маршрутизации](routing.ru.md) |
| `fallback-url` / `providerid` | Заранее переданный [резервный адрес](fallback.ru.md) и идентификатор для его сопоставления |
| `x-dodo-provider-id` | Публичный UUID провайдера для отдельной [интеграции с кабинетом](provider-console.ru.md) |

Обычные метаданные читаются сначала из реальных заголовков, затем из поддерживаемых комментариев тела, декодированного Base64 и JSON-метаданных. Используется первое корректное значение. В статическом файле допустимы поддерживаемые строки вроде `#profile-title: Demo Provider`.

**Исключение:** `x-dodo-provider-id` принимается только из успешного HTTPS-ответа с точного подтверждённого host, не из комментария. Не путайте его со старым полем `providerid` для резервного адреса. Ни одно из этих полей не подтверждает оплату или принадлежность ключа пользователю.

Не включайте секретный токен пользователя в адрес логотипа, поддержки и другие публичные ссылки. Сам по себе HTTP 403 не задаёт срок действия ключа.

## 3. Проверяйте лимит устройств на своём сервере

При запросе конфигурации DoDo передаёт ID установки и сведения об устройстве:

```http
User-Agent: DoDoApp
Accept: */*
x-hwid: 00000000-0000-4000-8000-000000000001
x-device-os: iOS
x-ver-os: 18.5.0
x-device-model: iPhone 14 Pro
```

В Android имена технических заголовков те же, но передаются его модель, версия ОС, `Android` и версионный User-Agent. HWID — не серийный номер и не IDFA. Повторный запрос не меняет ID; сброс настроек приложения не сбрасывает лимит устройств у провайдера. ID передаётся заголовком, не добавляется в URL.

| Ответ провайдера | Результат |
| --- | --- |
| `x-hwid-max-devices-reached: true` | Ошибка достижения лимита устройств |
| `x-hwid-limit: true` | Старый совместимый признак того же ограничения |
| `x-hwid-not-supported: true` или явный `HWID_REQUIRED` | Понятная ошибка загрузки без генерации нового ID |

Авторизацию и количество устройств проверяет провайдер. HWID не заменяет авторизацию. При переходе на другой origin iOS удаляет чувствительные заголовки, Android отклоняет переход; понижение HTTPS до HTTP запрещено.

## Ограничения и проверка перед запуском

| Ограничение | iOS | Android APK |
| --- | --- | --- |
| Ответ | 8 000 000 байт | 2 MiB |
| Вся операция | 12 000 000 байт | 4 MiB |
| Отдельный JSON-профиль | 2 000 000 байт | В пределах лимита ответа |
| Зашифрованное тело AGE1 | 2 MiB | 2 MiB |
| Общее время загрузки | 25 секунд, число попыток ограничено | 25 секунд, число попыток ограничено |

При ошибке проверка TLS не отключается. Частично загруженный ответ с сетевой ошибкой не импортируется.

До выдачи кнопки пользователям проверьте импорт, обновление, количество и порядок профилей, срок и трафик, сообщение о лимите устройств и реальное подключение на каждой нужной платформе. Используйте именно те транспорты и параметры авторизации, которые выдаёт ваша панель. Успешный импорт или TCP-пинг ещё не доказывает работу интернета.
