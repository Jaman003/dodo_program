## Подключение сервиса

Регистрация бесплатна и открыта в раннем доступе. Полный production-запуск ещё готовится. Войдите через Google в [DoDo Partners](https://api.dodoproxy.app/), создайте свой сервис и укажите публичный контакт поддержки. Пароль Remnawave, административный API-токен и доступ к VPN-нодам не нужны.

Для публичного бренда и сторис нужны три отдельные проверки:

1. Вход владельца через Google.
2. Подтверждение точного домена выдачи конфигураций через DNS TXT.
3. Одобрение сервиса командой DoDo.

Для `sub.example.com` запись выглядит так. Вместо примера используйте уникальное значение из своего кабинета:

```text
_dodo-verify.sub.example.com
dodo-verification=v1:КОД_ИЗ_ВАШЕГО_КАБИНЕТА
```

Проверка относится только к этому host, не ко всем поддоменам и не к другим сервисам на общем CDN. Подтверждение действует 30 дней. За семь дней до окончания появится предупреждение: получите новую TXT-запись и завершите продление вручную. Фонового автопродления нет.

## Заголовок provider ID

Добавьте настоящий HTTP-заголовок в успешный HTTPS-ответ выдачи конфигурации с подтверждённого host:

```http
x-dodo-provider-id: UUID_ВАШЕГО_ПРОВАЙДЕРА_ИЗ_DODO
```

Не помещайте его в JSON или комментарий тела. Страница ошибки, редирект и ответ другого host не подходят.

UUID публичный. Это не API-токен, премиум-доступ, подтверждение оплаты или принадлежности ключа конкретному человеку. Он отличается от короткого `providerid` для [резервных адресов](fallback.ru.md). Для публичного бренда и сторис не нужны модуль, signer или закрытый ключ подписи. Закрытому контенту абонентов потребуется отдельная проверка прав.

## Панель на своём сервере

[Скачать Provider Console 0.1.1](https://dodoproxy.app/providers/DoDo-Provider-Console-0.1.1.tar.gz) · [Инструкция по установке](https://dodoproxy.app/providers/DoDo-Provider-Console-0.1.1-README-RU.md)

Пакет запускается на вашем Linux-сервере через Docker Compose, за HTTPS-прокси на указанном точном адресе. Проверьте `SHA256SUMS` и следуйте инструкции из архива. Доступ к VPN-инфраструктуре с правами root, host network, Docker socket и модуль Remnawave ему не нужны.

Подтвердите установку через Google с одноразовым приватным кодом настройки, затем отдельно войдите как владелец или редактор. Одобрение установки не заменяет права человека. Каждая установка получает отзывной доступ только к своему провайдеру через центральный API DoDo. Основная админка, общие ключи платформы и push-учётные данные в пакет не входят. Данные и опубликованные медиа хранятся на стороне DoDo.

## Сторис и статистика

| Функция | Возможности и статус |
| --- | --- |
| Сторис | Черновик, предпросмотр, публикация на 12 или 24 часа, снятие с публикации и архив. Нужны действующий DNS, одобрение DoDo и совместимая новая iOS-сборка. В раннем доступе показ ограничен поддерживаемыми клиентами, не всеми установленными версиями. |
| Медиа | JPEG, PNG, WebP до 10 МБ; MP4 до 16 МБ и 30 секунд. Перед заменой медиа снимите сторис с публикации. |
| Аналитика по provider ID | Сервер и панель 0.1.1 подготовлены: агрегаты по моделям, ОС, версии DoDo и дням UTC; фильтры 1/7/30 дней и платформ. Новая установленная/опубликованная iOS-версия для этого учёта ещё не проверена. В Android этот механизм пока не перенесён. |
| Адресные push, закрытые сторис, автовыбор через API | Пока не готовы к общему использованию. Балансировщики внутри Xray JSON — отдельная функция. |
| Карта сетей | Закрытое тестирование. Remnawave подключается вручную с доступом только на чтение; собственным панелям нужен отдельный коннектор. Используются агрегаты, не `geoip.dat` / `geosite.dat`; без исходных IP и точного местоположения. Одного provider ID недостаточно. |

Сторис публичные: не размещайте секретные ссылки, сведения клиентов и материалы только для платных абонентов.

Существующие отчёты по `profile-title` и `support-url` доступны владельцу DoDo. Совпадение названия или контакта не даёт провайдеру права на эти записи. Для provider-ID отчётов нужны подтверждённый точный host и допуск сервиса.

Счётчик показывает установки с отчётами, не людей онлайн и не платящих абонентов. Одна установка может использовать несколько сервисов. В кабинет поступают агрегаты, без ключей, URL, HWID и списка отдельных устройств. Ограничение отправки — две попытки за 24 часа, не чаще 12 часов.

Сбой кабинета или API не должен мешать импорту и VPN. После таймаута записи обновите раздел и проверьте результат перед повтором. Ранний доступ не означает завершённый пилот у реального провайдера или неограниченную нагрузку.
